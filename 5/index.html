1.A.3 Warp the Images

To warp the images, we project the original image coordinates using our computed Homography matrix \(H\). Rather than using forward mapping (which causes holes and tears in the output image as source pixels diverge), I used an inverse mapping. In inverse mapping, we generate a grid for the target bounding box and map every target pixel back to the source image to sample its color. Essentially, we are ensuring that every pixel in the output pulls from a pixel in the source image, even if there are times where a source pixel is used more than once.

I implemented two interpolation methods to sample these source colors:

  • Nearest Neighbor Interpolation: This method takes the calculated floating-point source coordinate and rounds it to the nearest integer pixel. It is very fast to compute, but can result in jagged, aliased edges and visible pixelation. In my comparisons, I noticed that points in the image where there were supposed to be more subtle color changes ended up being a lot stronger. This is because there is no averaging in compression or stretching, so transitions are less smooth.
  • Bilinear Interpolation: This method looks at the 4 closest source pixels surrounding the exact floating-point coordinate and calculates a weighted average based on the coordinate's exact fractional distance to each pixel. While it takes more computation, it produces significantly smoother, higher-quality images by eliminating aliasing artifacts. In my own images, this produced color transitions that were much smoother compared to the nearest neighbor interpolation method.

1.A.4 Blend the Images into a Mosaic

To merge the aligned images into a seamless mosaic, overwriting one image with another leads to harsh, visible seams. I instead used an alpha mask and weighted feathering to make this a smoother transition.

Though I only used two images for these examples, this procedure can be done to create wider panoramas.

  1. Calculate the bounding box of the newly warped image to determine where it lands in space.
  2. Create a new global canvas large enough to hold both the base mosaic and the new warped image, shifting coordinates if the new image projects into negative space (up or left).
  3. Use a Distance Transform (specifically scipy.ndimage.distance_transform_edt) on the alpha mask of each image. This computes how far each valid pixel is from the edge of its respective image.
  4. Blend the overlapping regions by assigning higher weights to pixels furthest from their edges, smoothly transitioning opacity (alpha) linearly, with the value of 0 at the edge.

Initially, I tried computing the Homography matrix using only 4 point correspondences. Because a Homography has 8 degrees of freedom and each point provides 2 equations (\(x\) and \(y\)), 4 points give exactly 8 equations. Mathematically, this creates an exactly determined system.

This ended up being not very accurate since it was relying on just 4 points. This happens because human clicking is never perfectly accurate, so small errors force the exact mathematical solver to warp the entire image to force those imperfect points to align.

To fix this, I used 8 correspondences. By providing more points, the system becomes overdetermined. Since there is no longer a "perfect" solution that satisfies every single slightly-inaccurate click, I chose to solve using least squares. This minimizes the total sum of squared errors across all points that averages out the small human clicking errors.

When stitching multiple images together, the choice of the reference frame (the base image we warp everything else onto) drastically changes the calculated Homography matrices and the shape of the final mosaic. In my implementation, I chose to warp the left and right images onto the center image's coordinate space.

If I had instead chosen the far-left image as the reference frame, the right image would have to undergo a massive perspective shift to project onto a plane that is facing heavily away from its original view. Mathematically, as the angle between the viewing planes increases, the projected coordinates stretch out toward infinity. This causes extreme stretching, severe resolution loss (pixelation), and aggressive perspective distortion on the far side of the mosaic. By centering the reference plane, we minimize the maximum projection angle across the entire panorama, keeping the geometric distortion balanced.

1.B.1 Harris Corner Detection & Adaptive Non-Maximal Suppression (ANMS)

Harris Interest Point Detection: The Harris corner detector identifies interest points by searching for pixels with large intensity gradients in multiple directions. It calculates the structure tensor matrix $M$ using local image derivatives ($I_x$ and $I_y$) smoothed by a Gaussian window. The corner response score $h(x, y)$ is computed across the image to highlight sharp corners. While this detects thousands of valid corners, raw Harris responses tend to heavily cluster in dense, high-contrast areas (such as tree foliage or complex textures), leaving simpler regions sparse.

Adaptive Non-Maximal Suppression (ANMS): To ensure a uniform spatial distribution of interest points across the entire image, we implement ANMS. For every corner $i$, we find the minimum distance $r_i$ to another corner $j$ that has a significantly stronger corner response ($h_j > c_{\text{robust}} \cdot h_i$, where $c_{\text{robust}} = 0.9$):

$r_i = \min_j ||x_i - x_j||_2 \quad \text{subject to} \quad h_j > c_{\text{robust}} \cdot h_i$

Corners with large suppression radii $r_i$ represent strong local maxima over a wide spatial region. We sort all keypoints in descending order by radius $r_i$ and select the top $N = 500$ points, yielding well-distributed, high-scoring feature locations.

1.B.2 Feature Descriptor Extraction

To match interest points across different images, we extract a localized feature descriptor around each ANMS keypoint:

  • Anti-Aliasing Blur: We first apply a mild Gaussian blur ($\sigma = 1.0$) to the image to prevent aliasing during spatial downsampling.
  • Window Sampling & Downsampling: Around each keypoint, we extract a large $40 \times 40$ pixel bounding window. We sample every 5th pixel to downsample the window into a compact $8 \times 8$ patch (64 dimensions total). Sampling from a large $40 \times 40$ area gives the descriptor a larger context while maintaining a small vector size.
  • Bias and Gain Normalization: Each $8 \times 8$ patch vector $P$ is normalized to zero mean ($\mu = 0$) and unit variance ($\sigma = 1$) via $P_{\text{norm}} = \frac{P - \mu}{\sigma + \epsilon}$. This makes the feature descriptor invariant to linear illumination changes, brightness shifts, and contrast differences between photos.

Using the valid coordinates given from the feature descriptor, we can look at those patches in the photo in color. Edges in the color image reflect edges in the feature descriptor because these descriptors are just patches of the original image that have low pass filters applied and are then downsampled.

1.B.3 Feature Matching & Lowe's Ratio Test

We match features between Image 1 and Image 2 by calculating the pairwise Euclidean distance between all 64-dimensional descriptor vectors using scipy.spatial.distance.cdist.

Rather than setting a global distance threshold, we use Lowe's Ratio Test. For a descriptor in Image 1, we identify its 1st nearest neighbor (distance $d_1$) and 2nd nearest neighbor (distance $d_2$) in Image 2. The match was only considered valid when $\frac{d_1}{d_2} \lt \text{threshold}$. A lower threshold meant that the relative difference between the two distances had to be much larger, which excluded more candidates, while a higher threshold would allow for more repetitive features but could also result in too many inaccurate points being accepted.

Distinctive architectural corners (like window frames or door edges) produce a true match where $d_1 \ll d_2$, resulting in a small ratio. In contrast, ambiguous or repetitive patterns (such as tree leaves, grass, or clouds) match almost equally well to multiple patches in Image 2 ($d_1 \approx d_2$). Their ratio approaches $1.0$, allowing the test to discard false matches.

Finding these feature matches is possible even when the angle changes because around small patches like these, they are still roughly planar. The downsampling after applying a low pass filter as well as adjusting for lighting differences removes the slight geometric and shadow differences.

1.B.4 RANSAC for Robust Homography

Even after Lowe's ratio test, a small fraction of incorrect feature matches (outliers) can survive. Because standard least-squares homography is extremely sensitive to outliers, we implement 4-Point RANSAC:

  1. Random Sampling: Select 4 matched point pairs at random from the candidate matches.
  2. Candidate Homography: Compute the $3 \times 3$ Homography matrix $H$ mapping Image 1 points to Image 2 using Direct Linear Transformation (DLT).
  3. Reprojection Error & Inlier Counting: Transform all matched points from Image 1 using $H$ ($\hat{p}_2 = H p_1$) and calculate the Euclidean distance error to their actual location $p_2$ in Image 2: $$\text{Error} = \|\hat{p}_2 - p_2\|_2 = \sqrt{(\hat{x}_2 - x_2)^2 + (\hat{y}_2 - y_2)^2}$$ Points with a reprojection error below a distance threshold (e.g., $2.0$ pixels) are counted as inliers.
  4. Iteration & Refinement: Repeat this process for $N = 3,000$ iterations. We select the candidate homography matrix that produced the largest set of consensus inliers. Finally, we re-compute $H$ using all inliers in the best set via least-squares to obtain the optimal transformation.

When compared to the manual homography, the automatic version does a very good job of matching key features that might not be as noticeable to the human eye. Specifically, key features on the tree that might be harder to match just by looking are able to be more easily identified with the automatic. In addition, the least squares performance on inliers is far more points than the 8 selected for the manual, which is already difficult to keep track of.
