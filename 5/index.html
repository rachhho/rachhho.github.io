1.A.3 Warp the Images

To warp the images, we project the original image coordinates using our computed Homography matrix \(H\). Rather than using forward mapping (which causes holes and tears in the output image as source pixels diverge), I used an inverse mapping. In inverse mapping, we generate a grid for the target bounding box and map every target pixel back to the source image to sample its color. Essentially, we are ensuring that every pixel in the output pulls from a pixel in the source image, even if there are times where a source pixel is used more than once.

I implemented two interpolation methods to sample these source colors:

  • Nearest Neighbor Interpolation: This method takes the calculated floating-point source coordinate and rounds it to the nearest integer pixel. It is very fast to compute, but can result in jagged, aliased edges and visible pixelation. In my comparisons, I noticed that points in the image where there were supposed to be more subtle color changes ended up being a lot stronger. This is because there is no averaging in compression or stretching, so transitions are less smooth.
  • Bilinear Interpolation: This method looks at the 4 closest source pixels surrounding the exact floating-point coordinate and calculates a weighted average based on the coordinate's exact fractional distance to each pixel. While it takes more computation, it produces significantly smoother, higher-quality images by eliminating aliasing artifacts. In my own images, this produced color transitions that were much smoother compared to the nearest neighbor interpolation method.

1.A.4 Blend the Images into a Mosaic

To merge the aligned images into a seamless mosaic, overwriting one image with another leads to harsh, visible seams. I instead used an alpha mask and weighted feathering to make this a smoother transition.

Though I only used two images for these examples, this procedure can be done to create wider panoramas.

  1. Calculate the bounding box of the newly warped image to determine where it lands in space.
  2. Create a new global canvas large enough to hold both the base mosaic and the new warped image, shifting coordinates if the new image projects into negative space (up or left).
  3. Use a Distance Transform (specifically scipy.ndimage.distance_transform_edt) on the alpha mask of each image. This computes how far each valid pixel is from the edge of its respective image.
  4. Blend the overlapping regions by assigning higher weights to pixels furthest from their edges, smoothly transitioning opacity (alpha) linearly, with the value of 0 at the edge.

Initially, I tried computing the Homography matrix using only 4 point correspondences. Because a Homography has 8 degrees of freedom and each point provides 2 equations (\(x\) and \(y\)), 4 points give exactly 8 equations. Mathematically, this creates an exactly determined system.

This ended up being not very accurate since it was relying on just 4 points. This happens because human clicking is never perfectly accurate, so small errors force the exact mathematical solver to warp the entire image to force those imperfect points to align.

To fix this, I used 8 correspondences. By providing more points, the system becomes overdetermined. Since there is no longer a "perfect" solution that satisfies every single slightly-inaccurate click, I chose to solve using least squares. This minimizes the total sum of squared errors across all points that averages out the small human clicking errors.

When stitching multiple images together, the choice of the reference frame (the base image we warp everything else onto) drastically changes the calculated Homography matrices and the shape of the final mosaic. In my implementation, I chose to warp the left and right images onto the center image's coordinate space.

If I had instead chosen the far-left image as the reference frame, the right image would have to undergo a massive perspective shift to project onto a plane that is facing heavily away from its original view. Mathematically, as the angle between the viewing planes increases, the projected coordinates stretch out toward infinity. This causes extreme stretching, severe resolution loss (pixelation), and aggressive perspective distortion on the far side of the mosaic. By centering the reference plane, we minimize the maximum projection angle across the entire panorama, keeping the geometric distortion balanced.
